# 블루투스 모드 개선 계획 — Android Auto 없이 쓰는 Simple Radio

> 배경: Android Auto를 지원하지 않거나(또는 MINI처럼 차량이 자체 TMAP을 제공해) Android Auto
> 연결이 필요 없는 차량에서, **블루투스 오디오만으로** Simple Radio를 쓰려는 케이스.
> 작성: 2026-09-20 / 기준 v0.6.10 (versionCode 18). 착수 전 검토용.

---

## 0. 요약

- 보고된 블루투스 증상 4개(정보 미노출, 이전/다음 무반응, 단절 시 계속 재생, 재연결 시 미재개)는
  **모두 같은 원인**이다: **폰 화면의 재생이 MediaSession 없는 순수 ExoPlayer로 돌아간다.**
  블루투스(AVRCP)는 OS의 MediaSession을 통해서만 곡 정보를 받고 버튼을 보내므로, 세션이 없는
  재생은 차량 입장에서 "정체불명의 소리"다.
- 해결의 핵심은 **폰 재생을 차량용 서비스의 세션으로 통합**하는 것. 서비스에는 편성 정보·
  이전/다음=채널 전환·자동 재개·알림 등 필요한 것이 **이미 다 구현돼 있는데, 폰 화면이 그걸
  쓰지 않을 뿐**이다.
- 업데이트 배너 미노출은 별개 문제로, 릴리즈 자체는 정상(v18 latest, APK 첨부)이며 원인은
  앱의 "확인 시점·실패 처리"에 있다. 독립 작업이라 **병행** 가능하고, 먼저 작게 내보낼 수 있다.
- ⚠️ 데스크톱 포팅과 달리 이 작업은 **매일 쓰는 안드로이드 앱의 핵심(재생 경로)** 을 건드린다.
  Android Auto 경로를 서비스로 공유하게 되므로 **실차 Android Auto 회귀 검증이 필수**다.

## 1. 진단 (코드 근거)

| 증상 | 원인 | 근거 |
|---|---|---|
| ② 재생 정보가 차량에 안 뜸 | AVRCP 메타데이터는 활성 MediaSession에서 나온다. 폰 재생 경로엔 세션이 없다 | `core/media/MediaPlayer.kt`·`MainActivity.kt`에 MediaSession/MediaController 참조 0건 |
| ③ 이전/다음 버튼 무반응 | AVRCP 버튼은 활성 세션으로 배달된다. 받을 세션이 없다 | 동일. (서비스에는 "이전/다음=채널 전환"이 이미 구현됨) |
| ④ 블루투스 끊겨도 폰에서 계속 재생 | ExoPlayer `setHandleAudioBecomingNoisy(true)` 미설정. 출력 경로 소실(ACTION_AUDIO_BECOMING_NOISY)을 무시 | 폰·서비스 플레이어 모두 미설정 |
| ⑤ 시동 재시작 후 자동 재개 안 됨 | 재개는 (a) 헤드유닛이 보내는 AVRCP PLAY를 (b) 세션 기반 서비스가 `onPlaybackResumption`으로 받아야 한다. 서비스에 (b)는 있으나 폰 경로는 세션이 없고, 정지/재개 판단이 `CarConnection`(Android Auto)에만 묶여 있다 | `ARMSMediaLibraryService.kt:850` onPlaybackResumption 존재, `:196` isCarDefinitelyDisconnected |

**설계 배경**: PROJECT.md §3 "플레이어가 둘인 이유" — 차량용(서비스, 세션 있음)과 폰용(자체
ExoPlayer, 세션 없음)을 분리한 것은 Android Auto에서는 장점이었지만(연결 해제 격리), 블루투스
모드에서는 **바로 그 분리가 근본 원인**이다. 블루투스 모드는 "폰이 재생을 시작하되 차량이 그
재생을 알아야 하는" 모드라, 세션 기반이어야만 성립한다.

### 업데이트 배너 (⑥)
- 릴리즈 상태 정상: v18이 `releases/latest`, draft/prerelease 아님, `simple-radio-v18.apk` 첨부.
- 버전 비교 로직 정상(`v(\d+)` → versionCode 비교), 배너를 숨기는 "무시" 상태 없음.
- 문제 후보(코드 기준):
  1. **확인이 앱 콜드 스타트에만 실행**(`LaunchedEffect(Unit)`). 앱을 백그라운드에 오래 살려
     두면 며칠이고 재확인이 없다 — 가장 유력.
  2. **실패가 무음**: 응답 실패(`!isSuccessful`)면 null로 조용히 끝나고 "마지막 확인" 시각도
     안 남는다. GitHub API 비인증 한도(IP당 60회/시, 통신사 NAT 공유)에 걸리면 403 → 무음.
  3. 그 순간의 네트워크 실패.
- **adb 없이 진단**: 그 폰의 설정 footer "마지막 업데이트 확인" 시각. 오래됐거나 없으면 1·2번.
- UpdateChecker는 2026-07-11 이후 변경 없음 → 그 이후 버전이 깔린 폰이면 체커 자체는 동일.

## 2. 결정 사항 (착수 전 확인)

### 결정 1 — 플레이어 통합 방식 → **A. 폰 재생을 서비스 세션으로 통합** (권장)
폰 화면이 `core/media MediaPlayer` 대신 **`MediaController`로 `ARMSMediaLibraryService`에 재생을
요청**한다. 플레이어가 하나가 되고, 세션·메타데이터·버튼·알림·자동 재개를 모두 공유한다.
- 부수 효과(전부 이득): 폰 잠금화면/알림 미디어 컨트롤이 생기고, 포그라운드 서비스라 앱을
  스와이프해도 재생이 안 죽는다(지금은 액티비티 안의 플레이어라 취약).
- 데스크톱 포팅 Phase 1에서 만든 **`AudioPlayer` 인터페이스가 여기서 바로 쓰인다**: MainActivity는
  이미 그 계약으로 재생을 다루므로, `MediaController`를 감싼 `SessionAudioPlayer : AudioPlayer`를
  갈아끼우면 UI 변경을 최소화할 수 있다.
- 대안 B(폰 플레이어에 별도 세션 추가): 세션 로직이 둘로 중복되고 두 세션이 서로 경합한다. 비권장.

### 결정 2 — 블루투스 단절 시 동작 → **라디오는 정지, NAS는 일시정지**
현재 앱의 의미론과 동일(라디오 "일시정지"=정지). `setHandleAudioBecomingNoisy(true)` 한 줄이
OS 표준 신호를 받아 처리한다. 이어폰 뽑힘에도 같은 동작이 되는데, 이는 일반 앱과 같은 기대 동작.

### 결정 3 — 재연결 자동 재개 정책 → **헤드유닛 PLAY 신호 기반을 1차로, 기기 지정 옵트인을 2차로**
- 1차: 많은 헤드유닛은 연결 직후 AVRCP PLAY를 보낸다. 세션이 있으면 서비스의
  `onPlaybackResumption`이 그대로 받아 마지막 항목을 재개한다(코드 이미 있음, 차량 게이팅만 완화).
- 2차(MINI가 PLAY를 안 보낼 때만): A2DP 연결 브로드캐스트를 듣고 재개. **아무 블루투스 기기
  (집 이어폰 등)에나 자동 재생되면 안 되므로, 사용자가 "이 기기에서 자동 재개"로 지정한 차량
  기기에서만** 동작. `BLUETOOTH_CONNECT` 런타임 권한(API 31+) 필요.
- 어느 쪽이 필요한지는 **MINI 실차에서만** 알 수 있다(§4 Phase 1 검증 항목).

### 결정 4 — 업데이트 확인 시점 → **포그라운드 진입마다 확인하되 1시간 스로틀**
+ 실패를 무음으로 두지 않고 footer에 "확인 실패(사유)"를 남긴다.

## 3. 서비스에서 바뀌어야 하는 "차량 전용" 가정

서비스는 지금 "이 플레이어는 차량 전용"을 전제로 짜여 있다. 통합하면 이 전제들을 **재생 경로
(Android Auto / 블루투스 / 폰 스피커)를 아는 형태**로 일반화해야 한다.

| 현재 가정 | 위치 | 바꿀 것 |
|---|---|---|
| 차량(AA) 연결이 끊기면 즉시 정지+큐 폐기 | `onDisconnected`, `CarConnection` 관찰 | AA로 시작한 재생에만 적용. 폰/BT 재생은 becomingNoisy로 처리 |
| 차량 연결이 확인되지 않으면 포커스 재요청 안 함 (PROJECT §6.4) | 포커스 재시도 | "차량 또는 폰 화면이 활성"이면 허용 |
| 자동 재개는 차량이 확실히 끊긴 상태면 차단 | `isCarDefinitelyDisconnected` | BT 재개 경로는 이 조건에서 제외 |

이 표가 **회귀 위험의 실체**다. 각 항목은 Android Auto에서 실제 주행 로그로 잡은 버그의
해결책이므로(§6.3·6.4), 일반화하면서 AA 동작이 바뀌지 않는지 실차로 확인해야 한다.

## 4. 단계

### Phase 0 — 진단 확정 (반나절)
- 폰(S25/S22)에서 라디오 재생 중 `adb shell dumpsys media_session` → 우리 패키지의 세션이
  없음을 확인(진단 고정). 재생 중 BT 끊기 로그로 becomingNoisy 미처리 확인.
- 업데이트 배너: 미노출 폰의 footer "마지막 확인" 시각 확인(사용자). 비어 있으면 후보 1·2.

### Phase 4' — 업데이트 배너 ✅ 완료 (v19 / 0.6.11 릴리즈)
- 포그라운드 진입 시 재확인(1h 스로틀), 실패 사유 표시, 403(한도) 구분.
- 작고 독립적이라 Phase 1 개발과 **병행**하고, 먼저 릴리즈해 배너 자체를 실검증.

### Phase 1 — 세션 통합 ✅ 구현 완료 (0.7.0-rc1, 기기·실차 검증 대기)
- `SessionAudioPlayer : AudioPlayer`(MediaController 래퍼) 구현, MainActivity 재생 경로 교체.
- 서비스의 차량 전용 가정 일반화(§3). 재생 경로 개념 도입.
- `core/media MediaPlayer`는 통합 후 삭제 후보(데스크톱은 자체 구현이라 무관).
- **효과**: 증상 ②③ 해결 + 잠금화면 컨트롤 + 배경 재생 안정화.
- 게이트: 단위 테스트 전수 / 폰 회귀(라디오·NAS·즐겨찾기·이어듣기) / **실차 Android Auto 회귀**
  (연결 해제 정지, 시동 자동 재개, 셔플·반복, NAS) / **MINI 블루투스**(정보 노출, 이전/다음).
- MINI 검증 시 함께 기록: **시동 재시작 후 헤드유닛이 PLAY를 보내 저절로 재개되는가** → Phase 3 분기.

### Phase 2 — 블루투스 단절 시 정지 ✅ 구현 완료 (0.7.0-rc1에 Phase 1과 함께)
- 서비스 플레이어 `setHandleAudioBecomingNoisy(true)` + 경로 인지 정지 로직.
- Phase 1만 내보내면 "폰 재생이 서비스로 갔는데 BT 끊겨도 계속"이 그대로라 **반드시 같이** 낸다.

### Phase 3 — 재연결 자동 재개
- 3a: `onPlaybackResumption` 차량 게이팅 완화 → MINI에서 PLAY 신호로 재개되면 **끝**.
- 3b(3a 실패 시만): A2DP 연결 리스너 + "자동 재개 기기" 지정 UI + `BLUETOOTH_CONNECT` 권한.
  백그라운드에서 포그라운드 서비스를 시작해야 하므로 Android 12+ FGS 제한의 블루투스 예외
  적용 여부를 확인할 것(실패하면 알림 탭으로 재개하는 폴백).

**순서**: Phase 0 → (4' ∥ 1) → 2 → 실차 → 3.  4'는 병행, 1+2는 한 릴리즈.
